## 2. "Tasklist Agent" Specifications

This agent is designed to be the "minimal viable product" of a stateful agent. It doesn't just talk; it *modifies* its environment.

### A. The State Schema
The state must track both the conversation history (to understand context) and the actual data (the tasks).

```python
from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages

class Task(TypedDict):
    id: str
    title: str
    status: str # e.g., "pending", "completed"

class AgentState(TypedDict):
    # add_messages ensures new messages are appended to history
    messages: Annotated[list, add_messages] 
    # Our custom "database" within the state
    tasks: list[Task] 
```

### B. Defined Tools
The agent will have access to three primary Python functions:
1.  **`add_task(title: str)`**: Adds a new task to the state with a unique ID.
2.  **`update_task(task_id: str, status: str)`**: Changes the status of an existing task.
3.  **`delete_task(task_id: str)`**: Removes a task. **(This will be our "Interrupt" trigger)**.

### C. The Graph Logic
The graph should follow a specific "Safety First" flow:
1.  **Input Node:** Receives user message (e.g., "Delete the milk task").
2.  **Agent Node:** LLM decides it needs to call `delete_task`.
3.  **Interrupt Point:** The graph is configured to `interrupt_before=["action"]`.
4.  **Action Node (`ToolNode`):** Executes the tool only *after* the user provides a "go ahead" in LangGraph Studio.
5.  **Summarize/Response Node:** Confirms the action to the user.
